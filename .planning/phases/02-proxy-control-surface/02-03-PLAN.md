<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| proxy form inputs -> typed IPC commands | User-entered settings cross from the renderer to the host command surface |
| host invalidation events -> renderer refresh logic | Low-volume runtime events trigger UI refreshes |
| renderer status surface -> user decisions | UI presentation influences whether users believe the proxy is healthy or broken |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-07 | T | `src/features/proxy/state.ts` | mitigate | Mirror validation in the UI for fast feedback, but always treat Rust command validation as authoritative |
| T-2-08 | S | `src/lib/ipc/proxy.ts` | mitigate | Use named Tauri event constants for invalidation only and refresh from canonical commands instead of trusting event payload contents |
| T-2-09 | I | `src/components/proxy/ProxyControlPanel.tsx` | mitigate | Render only local endpoint, status, and non-secret error text; never surface secrets, SQL paths, or raw stack traces |
</threat_model>
